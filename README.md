# ATEC DocsAI — 오프라인 RAG 문서 검색 시스템

인터넷이 차단된 사내 PC에서 **로컬 문서를 내용 단위로 검색**하고, 필요할 때 **완전 오프라인 sLM으로 요약**까지 받아보는 데스크톱 애플리케이션입니다.

외부 API를 전혀 호출하지 않습니다. 검색·임베딩·요약이 모두 사용자 PC 안에서 끝납니다.

---

## 왜 만들었나

사내 문서는 pdf·docx·hwp·xlsx·pptx 등 형식이 뒤섞여 있어 형식마다 다른 프로그램으로 열어야 하고, 파일 안의 **내용**을 한 번에 검색할 방법이 없었습니다. 보안·네트워크 정책상 ChatGPT 같은 외부 클라우드 서비스도 쓸 수 없어, 문서가 쌓일수록 "어느 파일에 있었더라" 하며 파일을 하나씩 열어보는 시간이 누적됐습니다.

그래서 **인터넷 없이 동작하고, 관리자 권한 없이 폴더 복사만으로 배포되는** 검색 도구를 만들었습니다.

---

## 주요 기능

| 기능 | 설명 |
|---|---|
| 통합 검색 | 15개 확장자를 하나의 화면에서 내용까지 검색 |
| 하이브리드 랭킹 | FTS5/BM25 키워드 검색 + 임베딩 벡터 재순위 |
| 추출형 결과 | 기본값은 **원문 발췌** — LLM을 거치지 않아 즉시 표시되고 내용이 변형되지 않음 |
| AI 요약 (선택) | 사용자가 켤 때만 오프라인 sLM 실행, 4단계 할루시네이션 안전장치 |
| AI 챗봇 (선택) | 검색 결과를 근거로 후속 질문을 이어가는 2단 응답(즉시 발췌 → AI 요약) |
| 원문 열기 | 검색된 **위치**(페이지·문단·셀)로 원본 문서를 바로 열기 |
| 증분 인덱싱 | mtime → 해시 2단계 비교로 **변경된 파일만** 재파싱 |
| 실시간 감시 | 폴더 변경 감지 시 자동 재인덱싱 (옵션, 기본 OFF) |

## 동작 방식

```
문서 폴더
   │
   ├─ 파싱      형식별 파서 → 텍스트·표·이미지 청크로 분해
   │            (표는 행·열 구조 보존, 이미지는 별도 저장)
   ├─ 청킹      토큰 수 기준 분할 (문자 수 아님 — 자/토큰 비율이 0.50~2.70으로 흔들림)
   └─ 색인      SQLite FTS5 전문 색인 + 임베딩 벡터(BLOB) 동시 저장

검색 질의
   │
   ├─ 1차       한국어 조사 제거 → FTS5/BM25 로 후보 추출
   │            (파일명·표 캡션에 본문보다 높은 가중치)
   ├─ 2차       임베딩 코사인 유사도로 재순위
   │            정렬 키: 관련성 판정 → 검색어 일치 개수 → 본문 길이 → 유사도
   └─ 출력      원문 발췌 카드 (표는 그리드, 이미지는 썸네일)
                  └─ [선택] AI 요약 → 오프라인 sLM
```

**정렬 키에 "검색어 일치 개수"가 유사도보다 앞에 있는 이유**: 유사도만으로 정렬하면 검색어를 모두 담은 문단이 한 단어만 걸린 짧은 조각에 밀립니다(실측으로 확인된 문제).

## 할루시네이션 방지 — 4단계

| 단계 | 장치 | 동작 |
|---|---|---|
| 1 | 사전 차단 | 유사도가 임계값(0.5) 미만이면 **sLM을 호출하지 않음** |
| 2 | 근거 강제 | 발췌 밖의 지식으로 답하지 못하도록 프롬프트에서 제약 |
| 3 | 결정론적 출처 | 모델은 `[1]` 같은 **번호만** 반환, 코드가 `[파일명, 위치]`로 치환 |
| 4 | 교차 검증 | 생성된 문장과 근거 발췌를 문자 bigram 겹침도로 대조 |

3단계가 핵심입니다. 4B급 모델에게 파일명을 직접 쓰게 하면 **파일명 자체를 지어낼** 여지가 생기므로, 모델이 출처 문자열을 만들 수 없게 설계했습니다.

## 지원 형식

| 분류 | 확장자 | 원문 열기 시 위치 이동 |
|---|---|---|
| PDF | `.pdf` | ✅ 페이지 (기본 뷰어가 Edge일 때) |
| Word | `.docx` `.doc` | ✅ 문단 |
| Excel | `.xlsx` `.xls` | ✅ 시트·셀 |
| PowerPoint | `.pptx` | ✅ 슬라이드 |
| 〃 | `.ppt` | 파일만 열림 |
| 한글 | `.hwp` `.hwpx` | 파일만 열림 |
| 텍스트 | `.txt` `.md` `.csv` `.log` `.rtf` `.xlsm` | 파일만 열림 |

> 위치 이동은 Office COM(Word/Excel/PowerPoint 설치 필요)과 Edge PDF 뷰어로 구현했습니다. 해당 프로그램이 없거나 실패하면 **조용히 기본 프로그램으로 파일을 여는 폴백**이 동작합니다 — "파일이 열리기는 한다"는 보장은 어떤 경우에도 깨지지 않습니다.
>
> 구버전 포맷(`.doc` `.xls` `.ppt`)의 **인덱싱**에는 LibreOffice 변환이 필요합니다(`vendor/LibreOfficePortable/`). 없으면 해당 파일은 실패로 표시됩니다.

## 모델

**임베딩** (검색 정확도)

| 모드 | 모델 | 차원 | 최대 길이 | 비고 |
|---|---|---|---|---|
| 경량 | `jhgan/ko-sroberta-multitask` | 768 | 128 | 프로그램에 포함 |
| 권장 | `nlpai-lab/KURE-v1` | 1024 | 8192 | 별도 변환 필요, CLS 풀링 |

**sLM** (AI 요약 · 선택 설치)

| 모드 | 모델 | 크기 | 권장 메모리 |
|---|---|---|---|
| 경량 | EXAONE 4.0 1.2B | 0.81 GB | 8 GB |
| 권장 | Qwen3.5 4B | 2.74 GB | 16 GB |

sLM은 용량 때문에 저장소에 포함하지 않습니다. 앱의 **설정 → 모델 관리**에서 직접 내려받거나, 인터넷이 되는 PC에서 받아 `models/slm/`에 복사하면 됩니다.

## 설치 및 실행

```bash
py -3.14 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m indexer.vector.download   # 임베딩 모델 (최초 1회, 인터넷 필요)
./.venv/Scripts/python.exe run_app.py
```

빌드(배포용 exe):

```bash
./.venv/Scripts/python.exe -m deploy.build
```

LibreOffice 포터블(1.5 GB)을 빼고 빠르게 빌드하려면 `--skip-libreoffice`를 붙입니다. 이 경우 구버전 포맷(`.doc` `.xls` `.ppt`) 인덱싱은 동작하지 않습니다.

**Python 3.14 기준**입니다. `torch`는 의도적으로 넣지 않았습니다 — 사용하는 모델이 int8 ONNX를 제공해 추론에 필요 없고, torch만으로 설치 용량이 크게 늘기 때문입니다.

## 설계상 특징

- **레지스트리를 쓰지 않고 상대 경로로만 동작** — 관리자 권한 없이 폴더 복사만으로 배포·이전
- **인덱스는 PC마다 생성해야 함** — int8 양자화 활성값 스케일이 CPU에 따라 달라, 다른 PC에서 만든 인덱스를 가져오면 검색 순위가 무너집니다(top10 겹침 4~8/10). 같은 PC 안에서는 top1 전부 일치
- **`doc_id`는 파일 내용이 아니라 절대경로 해시** — 파일을 옮기면 새 문서로 인식됩니다
- **이미지 자산은 `data/assets/`로 중앙화** — 사용자 문서 폴더에 쓰기를 하지 않습니다(OneDrive 동기화 부작용 방지)
